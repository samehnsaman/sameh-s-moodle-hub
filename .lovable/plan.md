# Sameh Naim — Freelance Moodle Developer Portfolio

Two-part delivery in one repo:
- **Frontend (runs on Lovable now)** — TanStack Start + TypeScript + Tailwind, fully responsive.
- **Backend scaffold (`backend/` folder, you deploy on your VPS)** — Express + TypeScript + Prisma + PostgreSQL + Docker Compose. Files only; not executed by Lovable.

The frontend works immediately with seeded local content, and switches to your real API by setting one env var (`VITE_API_BASE_URL`).

---

## 1. Frontend (Lovable)

### Pages & routes

| Route | Page | Purpose |
|---|---|---|
| `/` | Home | Hero, services overview, featured projects, tech stack badges, testimonials, CTA |
| `/projects` | Projects listing | Filter bar (All / Moodle Plugin / SaaS / School Management / WordPress), grid of cards |
| `/projects/$slug` | Project detail | Problem, Solution, Tech stack, Outcomes, Links |
| `/services` | Services & Skills | Service cards + skills grouped by category |
| `/about` | About | Bio + timeline of milestones |
| `/contact` | Contact | Form (name, email, organization, project type, budget range, message) |

Each route has its own `head()` with unique `title`, `description`, `og:title`, `og:description`.

### Design

- Clean developer-portfolio aesthetic. Neutral palette (slate/zinc) with one accent color (electric blue).
- Typography: Inter for body, tight tracking on headings.
- Shared header with active-link highlighting + footer with location ("Cairo, Egypt") and social links.
- Responsive: mobile drawer nav, tablet/desktop horizontal nav.
- Uses existing shadcn/ui components (Button, Card, Badge, Input, Textarea, Select, Sonner toasts).

### Frontend data layer

- `src/lib/api-client.ts` — typed fetch wrapper. Base URL = `import.meta.env.VITE_API_BASE_URL` if set, otherwise falls back to local seed data. This means:
  - **Today on Lovable**: site renders with realistic seed content, no backend needed.
  - **After you deploy backend on VPS**: set `VITE_API_BASE_URL=https://api.yourdomain.com`, frontend automatically calls it.
- `src/lib/seed-data.ts` — single source of truth for fallback content (profile, skills, services, projects). Easy to edit by hand.
- `src/types/portfolio.ts` — shared TS interfaces (`UserProfile`, `Skill`, `Service`, `Project`, `ContactMessage`) — same types used by backend.
- Contact form `POST`s to `${API_BASE_URL}/api/contact`. If no API base URL is set, it shows a friendly message: "Backend not configured yet — please email me at …" so the form is never broken.

## 2. Backend scaffold (`backend/` — you deploy on your VPS)

Files generated into the repo. Not run by Lovable. You clone the repo to your VPS and run it there.

### Structure
```text
backend/
  src/
    index.ts              Express app entry
    routes/
      profile.ts          GET /api/profile
      skills.ts           GET /api/skills?category=
      services.ts         GET /api/services
      projects.ts         GET /api/projects?type=&featured=
      project-by-slug.ts  GET /api/projects/:slug
      contact.ts          POST /api/contact (Zod-validated)
    lib/
      prisma.ts           Prisma client singleton
      validation.ts       Zod schemas
    middleware/
      cors.ts             CORS for your frontend domain
      error-handler.ts
  prisma/
    schema.prisma         Full data model (Postgres)
    seed.ts               Seeds with the same realistic content as frontend
    migrations/           (generated by `prisma migrate dev`)
  Dockerfile
  package.json
  tsconfig.json
  .env.example            DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME, FRONTEND_ORIGIN
docker-compose.yml        Postgres 16 + backend service
README.md                 Full setup instructions
```

### Data model (Prisma / Postgres)

- `UserProfile` — id, name, location, title, shortBio, avatarUrl, yearsExperience
- `Skill` — id, name, category, level, icon
- `Service` — id, title, shortDescription, detailedDescription, targetClients
- `Project` — id, name, slug (unique), shortDescription, longDescription, techStack (String[]), role, startDate, endDate?, status, featured, projectType, liveUrl?, demoUrl?, githubUrl?
- `ContactMessage` — id, name, email, organization?, message, budgetRange?, projectType?, createdAt, status (default "new")

### API endpoints

All return JSON, all match the contracts the frontend already calls.

- `GET /api/profile`
- `GET /api/skills` (optional `?category=`)
- `GET /api/services`
- `GET /api/projects` (optional `?type=`, `?featured=true`)
- `GET /api/projects/:slug`
- `POST /api/contact` — Zod-validates name (required, ≤100), email (required, valid, ≤255), organization (≤200), message (required, ≤2000), budgetRange (enum), projectType (enum). Returns `{ success, id }` or `{ success: false, errors }`.

### README setup steps

1. `cp backend/.env.example backend/.env` and fill in DB credentials.
2. `docker compose up -d` (starts Postgres + backend).
3. `cd backend && npx prisma migrate deploy && npx prisma db seed`.
4. Backend listening on `:4000`.
5. On the frontend (Lovable or your own host), set `VITE_API_BASE_URL=https://api.yourdomain.com`.
6. Point Nginx/Caddy reverse proxy at `:4000` with HTTPS.

## Out of scope (intentional)

- No Supabase / Firebase / hosted BaaS.
- No auth — site is public, contact form only.
- No admin UI for editing content (you edit via DB or seed file; can add later).
- Backend will not run inside Lovable's preview — that's expected, it lives on your VPS.

## Technical notes

- TanStack Start + Vite + React 19 + Tailwind v4 (already in this project).
- All shared types in `src/types/portfolio.ts` are duplicated into `backend/src/types/` so both sides stay in sync; alternatively you can later extract a shared package.
- CORS in backend is locked to `FRONTEND_ORIGIN` env var.
- Contact endpoint should add basic rate limiting (`express-rate-limit`) before going live — included in scaffold.
- No secrets in frontend bundle. `VITE_API_BASE_URL` is the only frontend env var, and it's a public URL.
